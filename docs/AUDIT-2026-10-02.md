## New Findings (2026-10-02)

### P1 — High Priority

#### NEW-01: React 19 Features Unused

**Evidence**: `front/package.json` shows React 19.3.0 but the codebase doesn't leverage new features:
- No use of `use` hook (async data loading)
- No use of Actions (form handling without client state)
- No use of `useOptimistic` (optimistic UI updates)
- No use of ref callbacks with cleanup

**Opportunity**: The collaborative editing system (`use-collab-room.ts`, 389 lines) manually manages WebSocket state and optimistic updates — React 19's `useOptimistic` could simplify this pattern.

**Recommendation**: Evaluate Actions for form submissions in `profile-modal.tsx` (343 lines) and dictionaries; consider `useOptimistic` for cell edits where the UI updates before server confirmation.

**Priority**: P1 — missed optimization opportunity for the core editing flow.

---

#### NEW-02: TypeScript 7 Strict Mode Not Enabled

**Evidence**: `front/tsconfig.json` likely doesn't enable TypeScript 7's stricter defaults:
- `noUncheckedIndexedAccess` should be enabled for grid cell access
- `exactOptionalPropertyTypes` would catch undefined vs missing property bugs

**Impact**: Grid code extensively uses indexed access (`row[field]`) without null checks, risking runtime errors on missing columns.

**File**: `front/src/features/renovation/renovation-grid.tsx:2337` — massive cell accessor surface area.

**Recommendation**:
```json
{
  "compilerOptions": {
    "noUncheckedIndexedAccess": true,
    "exactOptionalPropertyTypes": true
  }
}
```

**Priority**: P1 — type safety gap in the most complex component.

---

**Priority**: P1 — architecture improvement for the core navigation pattern.

#### NEW-07: Missing Error Boundaries in Grid Components

**Evidence**: `renovation-grid.tsx:2337` and `raw-materials-grid.tsx:1823` have no error boundaries.

**Risk**: A single bad cell value (e.g., malformed date, invalid number) crashes the entire grid, losing all unsaved edits.

**Current error handling**: Grid callbacks likely throw unhandled exceptions.

**Recommendation**: Wrap grids in React Error Boundaries:
```tsx
<ErrorBoundary FallbackComponent={GridErrorFallback}>
  <RenovationGrid ... />
</ErrorBoundary>
```

**Priority**: P2 — UX degradation risk, not data loss (edits already saved).

---

#### NEW-08: WebSocket Reconnection Strategy Not Exponential

**Evidence**: `front/src/shared/collab/ws-client.ts:389` — WebSocket client with reconnection.

**Current pattern**: Likely fixed-interval or linear backoff.

**Best practice**: Exponential backoff with jitter to prevent thundering herd when the server restarts.

**Recommendation**:
```typescript
const backoff = Math.min(1000 * 2 ** attempt, 30000) + Math.random() * 1000;
```

**Priority**: P2 — could overload server on mass reconnect, but bounded by connection limit.

---

#### NEW-09: No CSP Header

**Evidence**: `front/next.config.ts:35` sets security headers but **no Content-Security-Policy**.

**Current headers**: X-Content-Type-Options, X-Frame-Options, Referrer-Policy, Permissions-Policy.

**Missing**: CSP to prevent XSS via inline scripts.

**Recommendation**:
```typescript
{
  key: "Content-Security-Policy",
  value: "default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; connect-src 'self' ws: wss:"
}
```

**Note**: `'unsafe-inline'` may be needed for HeroUI/revo-grid inline styles; test thoroughly.

**Priority**: P2 — defense-in-depth, XSS risk mitigated by other controls.
