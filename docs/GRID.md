# Grid (frontend, revo-grid)

Main code: `front/src/shared/grid/` (`raw-materials-grid.tsx` — the grid component, `grid-config.ts` — forms/columns config, `grid-edit.ts` — edits, `grid-editors.tsx` — cell editors, `section-tabs.tsx` — form tabs). Orchestration: `front/src/features/raw-materials/raw-materials-workspace.tsx`.

Stack: `@revolist/react-datagrid` 4.25 (revo-grid), React 19, HeroUI (tooltips, modals, toasts), Tailwind 4, Next 16. Custom editors are registered through `revo-grid` (see `grid-editors.tsx`).

## Forms and columns (`grid-config.ts`)

- `SectionId`: `materialMovement` («Движение»), `rawMaterialPrices` («Цены»), and the dictionaries `rawMaterials`, `assets`, `deliveryBases`, `users`. `MAIN_SECTIONS` = movement+prices; dictionaries are admin-only. The `users` table shows «Время последнего входа» (`lastAuthenticatedAt` from `app_users`, read-only `datetime` column) — the last successful authentication (Keycloak or local), null until the user has logged in. The «Сбросить пароль» action column is hidden when Keycloak is enabled (passwords are managed in Keycloak) — flag flows through `GridColumnContext` into `getVisibleDescriptors`/`editableFieldKeys`/export.
- `ColumnDescriptor`: key, label, width, kind (`text|number|boolean|asset|assetsMulti|basis|datetime|calculated`), `fixed` (pinned, non-editable), `path` (nested header, e.g. «Потребность / План, т»), `adminOnly`, `exportable`, placeholder flags.
- Merged headers (`ColumnGrouping`) are built from `path`; editors: `reference` (single pick from `source`), `multiAssets` (multi-pick), booleans — checkbox template.
- Each row is a `GridRow`: id, `rowState` (`unchanged|new|deleted`), `changedFields`, `isDeleted`, `canonicalCells` (canonical cell keys), `isPlaceholder` (the trailing «добавить запись» row). Its row-header button shows **«+» instead of a number** («Добавить строку» tooltip) — same as the renovation plan grid.
- Default sort: raw-material items first, then assets; placeholder/deleted always at the end (`placeholderLastCellCompare`).
- Form reads: «Движение» — `GET /movement?report_month=`, «Цены» — `/prices`; dictionaries — their own GETs. Edits — `PATCH /movement`, `/prices`, `updateDictionaryCells`; one edit = a batch `{rowId, field, value}`.
- **«Бизнес-план, т» in «Движение» is a projection from «Цены», non-editable; in «Цены» business-plan edits go to `RawMaterialPrice` and are not "projected" onto other forms.**

## Clipboard

`raw-materials-grid.tsx`, "clipboard" section (functions `copySelection`, `pasteIntoSelection`, `cutSelection`, `buildCopyText`).

- **Copy (Ctrl+C)** — by value: numbers as-is (`,` for decimals), multi-dictionaries — joined with `,`; the copy goes to the system clipboard (`navigator.clipboard`).
- **Paste (Ctrl+V)** — the whole path goes through `rangeeditapply` → `beforeRangeEdit`, so locks/validation and undo/redo work uniformly:
  - Dictionary fields: single dictionary — the value must match an option; multi (`assetsMulti`) — `split(",")`, **each** value `str.strip()`-looked up among options, otherwise the paste is rejected (toast). When pasting dictionary rows, values are mapped to **existing UUIDs** (by value after strip).
  - Sizes: one cell selected → paste everything starting from that cell; ≥2 cells selected → paste only into the selected range: if the pasted range is bigger — it's **trimmed** by the range (toast), if smaller — pasted as-is, other cells untouched.
  - **Excel buffer**: trim trailing empty rows and columns (Excel puts a trailing `\n`) — otherwise an extra empty cell below overwrites a neighbor.
  - **Numbers**: any Unicode whitespace is accepted as a thousands separator (regular space, NBSP, narrow NBSP — Excel uses different ones), `,` becomes `.`. Front: shared `parseNumericText` (`front/src/shared/grid/grid-edit.ts`, used by both grids); back: `coerce_number` (`raw_materials/service.py`) and the seed parser — keep them in sync.
  - After paste the selection moves to the pasted cells and goes to presence.
- **Ctrl+X** — like Ctrl+C but clears the source cells (empty value; multi — empty list; boolean fields skipped). Through the same `rangeeditapply` → busy cells are skipped, the operation lands in undo/redo.
- **Hotkeys — by `event.code`** (`KeyC/KeyV/KeyX/KeyZ/KeyY`), otherwise broken with the Russian layout. Ctrl+Z/Y — undo/redo (server-side stack, see `docs/COLLAB.md`). **Undo race guard:** the workspace keeps the in-flight commit promise in `pendingCommitRef` and `runUndo`/`runRedo` await it first — a Ctrl+Z pressed right after Enter would otherwise reach the server before the PATCH journaled the edit and silently do nothing (observed as an e2e flake under load).
- The paste button («Вставить») only works when the buffer is compatible with the selection (`canPasteRange`) — also through the visible row source.

## Selection

- **Ctrl+A — fully custom**: a `document` handler in the capture phase with `stopImmediatePropagation` (kills revo-grid's built-in select-all, which draws three torn frames — header/data/bottom). Selects one contiguous range over the data cells, **without headers and without the «добавить запись» row**.
- **Programmatic selection — only through the grid's public API**: `grid.setCellsFocus(start, end)` + `grid.refresh()` (without `refresh` Stencil doesn't redraw the overlay). Reset — `grid.clearFocus()` + `grid.refresh()`: the store empties, but without `refresh` the old range rectangle stays visible. **`store.setRange` doesn't exist** (in `revogr-overlay-selection` there's a raw observable without methods) — it's dead code, don't use it.
- Row selection (click/shift/ctrl on the row number) **resets** the cell selection (`clearGridSelection`) — both state and the visual frame. **Order matters**: the range is cleared **before** `setSelectedRowIds` — the row selection rebuilds `columns` (selectedRowIds is a `columns` dependency) and revo-grid's `columnChanged` captures the still-live focus into `pendingColumnFocusRestore`, which `restoreColumnFocusAfterRender` then re-applies as a single-cell range (its guard can't match an empty store). `clearGridSelection` also drops the stale restore for the same reason.
- **Escape on the «Ремонт» grid additionally bumps `selectionEpoch`** (a `columns` memo dependency) **after** `clearGridSelection`: with a plain range (no row selection) `setSelectedRowIds([])` changes nothing, no columns rebuild happens, and the selection overlay does **not** reliably repaint on a bare store change — the rectangle stays until the next keypress. The forced rebuild repaints the overlay from the already-empty store (safe: `columnChanged` finds no focus to restore — same reasoning as row clicks). The «Сырьё» grids don't need it: their selected-row classes live in `rowHeaders`, not `columns`, and their overlay repaints correctly on `clearFocus` + `refresh`.
- A mouse-dragged selection is sent to presence **only on completion** (`setrange`), not live.

## Pinned header and scrollbars

- The «Закрепить заголовок» option (grid options menu, ⋮) is **on by default** (`headerPinned` state in `raw-materials-workspace.tsx`). Pinned mode: the grid fills the shell (`revo-grid-shell--pinned`), revo-grid scrolls internally (sticky header stays visible), its own virtual scrollbars (`revogr-scroll-virtual.vertical/.horizontal`) drive the viewport. Unpinned: an external vertical scroller plus a custom horizontal strip (`revo-grid-external-scrollbar`), the grid is sized to its content (`--grid-content-height`).
- **Scrollbars are the browser's native ones, no custom styling.** revo-grid hides its raw viewport scrollbars (`scrollbar-width: none`) and renders `revogr-scroll-virtual` strips whose *own* native scrollbars are the visible bars — they're real light-DOM elements, and revo-grid sizes them to the measured system scrollbar width, so pinned and unpinned bars naturally match. **Landmine**: revo-grid's light theme sets `color-scheme: light` on the host → native scrollbars render light even in the app's dark theme; `globals.css` fixes it with `.dark .raw-materials-grid { color-scheme: dark }` — keep that override if the `theme` prop changes.
- Scrollbars appear only when there's overflow (native `overflow: auto`); `revogr-scroll-virtual` collapses to 0 size without overflow (revo-grid sets its min-size to 0 in `componentDidRender`). In unpinned mode the external strip is hidden when the content fits (`revo-grid-shell--no-hscroll`, `hasHorizontalOverflow` state) — no dead 17px gap under the last row.
- **In unpinned mode BOTH internal scrollbars are hidden** (`revogr-scroll-virtual`, not just `.horizontal`) — the external scroller and the external horizontal strip own the scrollbars there. Without hiding the internal vertical one, its native scrollbar lingers next to the external bar right after unpinning (its spacer keeps the old height until revo-grid's async re-measure) — the "duplicated scrollbar" flicker. **Landmine**: hiding is done by zeroing the strip sizes (`width/height: 0 !important` + `min-width/min-height: 0 !important` in `globals.css`), **not** by `visibility: hidden` alone — revo-grid sets an inline `min-width/min-height` on the strip hosts (which would win), and Firefox paints the native scrollbar of a `visibility: hidden` scroll container (the "dead strip" after unpinning). A zero-size strip has no scrollbar to paint in any browser. **In pinned mode the «Ремонт» grid pins its horizontal strip to 17px whenever there's overflow** (`.revo-grid-shell--pinned .renovation-grid revogr-scroll-virtual.horizontal` + `.revo-grid-shell--no-hscroll` to collapse it when everything fits — the class is now applied in pinned mode too; the unpinned-only rules that key off it are inert there): revo-grid's `AutohideScrollPlugin` would otherwise shrink the strip 1s after scrolling (the bottom bar "hides after hovering") — on Chrome (overlay scrollbars since 121) `getScrollbarSize` returns 0, the strip's inline min-height collapses to 0 and the plugin shows it 20px for a second per scroll; the «Сырьё» grids show it always. The `::-webkit-scrollbar` rule for the strip forces classic always-visible scrollbars there (any webkit scrollbar styling disables the overlay mode for that element); `!important` sizes beat revo-grid's inline `min-height` and the plugin's `[visible]` rule (this stylesheet loads later).
- **Wheel over the horizontal scrollbar scrolls it horizontally** (native Chrome behavior scrolls the vertical axis instead). A native `wheel` listener on the shell (`{ passive: false }` — React's `onWheel` is passive and can't `preventDefault`) detects the cursor over `revogr-scroll-virtual.horizontal` (pinned) or the external strip (unpinned) and translates `deltaY + deltaX` into `scrollLeft`; the strips proxy to the viewport via revo-grid's `scrollvirtual` events.

## Coordinates: sorting and filtering (the most important landmine)

Under sorting/filtering the screen row index **doesn't match** the `rows` index (the source array is unsorted). Anything mapping "index → row" must use **`getVisibleRows()`** (`grid.getVisibleSource("rgRow")` — the current sorted/filtered source): paste (building `models`), cut, copy (including the context menu), presence (my selected keys), `canPasteRange`. Otherwise values are committed to the wrong row → fake asset "deletions" → RESTRICT error (symptom: «ошибка удаления актива» when pasting on a sorted sheet).

Inline it is a row: the status badge (dot) on the **left, vertically centered** against the stacked lines `<b>На форме:</b> …` / `<b>Выделено:</b> …`; the HeroUI tooltip spells out «Выделено» and «Строки»/«Столбцы» first, then the member presence list. «На форме» uses last names only, **«вы» is lowercase**, role «админ» (not «Администратор»), for an asset worker — the **concrete asset list**; full FIO and cell ranges — only in the tooltip.
- **Top vs bottom panels:** the top (toolbar + view strip) holds display-only controls — presence/selection summary, tabs, asset/block filters, export/fullscreen; the bottom footer holds actions and data scope — the version picker («Рабочая версия»), undo/redo/copy/paste/add/delete/submit/approve.
- **View strip** (`.view-strip`, between the toolbar and the grid): one row, `justify-content: space-between` — on the left the filters (only where they exist: the «Ремонт» plan gets a content-sized asset `SearchAutocomplete` + block `Select`) followed by the **«Закрепить заголовок» / «Показать служебные столбцы» switches** (`.view-strip__toggles`, HeroUI `Switch` compound: `Content > Control > Thumb`), and on the right the **shared `ViewStrip`** (`front/src/shared/ui/view-strip.tsx`) controls: an Excel export dropdown («Скачать всю таблицу» / «Скачать видимую таблицу», `variant="tertiary"` button), a **reset dropdown (`variant="danger"`, its items danger too)** — «Сброс ширины столбцов» and «Сброс всех фильтров и сортировок» — and the fullscreen toggle (`variant="tertiary"`). All three, plus the compact «Действия»/«Таблица» menus and the `AppHeader` project switcher, open on **hover** (`HoverDropdown`); the action bars default to `variant="tertiary"` (`action.variant ?? "tertiary"`). While a hover dropdown is open, react-aria inerts the rest of the page, which drops the trigger's `:hover` and collapses its label — so `HoverDropdown` passes `isOpen` to the trigger and the view-strip export/reset buttons add an `action-button--open` class (kept label/gap) for the duration. The toggles are fully controlled: both grids take `headerPinned`/`showServiceColumns` props, state lives in the workspaces (raw: one pair for all sections; renovation: separate pairs for the plan and dictionaries). **Below md (< 48rem)** the switches and all right-side controls collapse into one hover menu («Настройки таблицы», MoreVert trigger) whose entries carry a leading check for active toggles. **Responsive sizing:** HeroUI's theme ships sm:/md: variants that resize controls across breakpoints; globals.css freezes --breakpoint-sm/--breakpoint-md to 0rem in @theme, so every component renders its roomier base look at all viewports (the app itself uses no sm:/md: utilities). Don't reintroduce custom per-breakpoint size pins for chrome controls. «Видимая таблица» exports the rows currently on screen: raw passes `getExportState().rowIds`; the renovation plan POSTs `/plan/export {planId?, rowIds}` (visible ids from `RenovationGridHandle.getVisibleRowIds`); renovation dictionaries pass `state.rowIds`. Reset wiring: grids expose `resetColumnWidths()`/`resetFiltersSorting()` on their handles (raw clears its in-memory width map + bumps `widthsVersion`; renovation clears its localStorage `renovation:colWidth:*` keys; filters/sorting = plugin clear + `clearSorting`, for the plan grid = workspace asset/block filter reset); sections register them upward via the `onResetState` callback (the same pattern as `onExportState`). In fullscreen the in-flow strip collapses to zero height together with the toolbar/footer (`max-height: 0`) so the grid reclaims the viewport, while the same JSX renders on the floating top panel.
- **Action bar grouping:** consecutive `ActionItem`s sharing `group` render joined in one HeroUI `ButtonGroup` (`groupActionItems` in `raw-materials-workspace.tsx`): undo+redo share `"history"`, copy+paste share `"clipboard"`. The compact «Действия» menu stays flat.
- **One account in several tabs** — the backend keeps one presence entry per user, so the tabs share it ("last writer wins"): when a `presence:update` arrives where my user's selection differs from what this client last sent (another tab took over), the local grid selection is cleared **silently** (`onSelectionPreempted` in `ws-client.ts` → the workspace clears the grid via the `clearSelection` handle; the resulting empty presence send is swallowed by `suppressSelectionSendRef` in `SectionContent` — otherwise the tabs would clear each other in a loop). The stale `lastSelection` is dropped so a reconnect doesn't resurrect it.
- **Tooltips — HeroUI `Tooltip`, not native** (for presence and busy cells; positioning reference — ReportCollector-RawMaterials). In the tooltip: full FIO as an unordered list, role/assets in parentheses, the cell range under the FIO in normal (not bold) font, the column name in quotes («Потребность / План, т»). `white-space: nowrap` + `max-width: none` — no word wrapping («Земелькин Сергей Александров\nич» is unacceptable).
- Yellow highlight of cells occupied by others (completed selection) with a "FIO — range" tooltip.
- In the archive «Движение» / «Ремонт» version presence isn't maintained — «На форме» isn't shown at all (`FormStatus` gets `room={null}`).

## Responsive layout (below lg, `@media (width < 64rem)`)

A split-screen tab (≈ half a desktop) triggers the compact shell; one `@media (width < 64rem)` block in `globals.css` plus two components (`raw-materials-workspace.tsx`):

- **Header:** the middle spacer column is dropped (`grid-template-columns: minmax(0,1fr) minmax(0,auto)`, spacer `display: none`); «РепортКоллектор» may ellipsize, «Сырьё» never does — and keeps `line-height: 1.2` with **no `overflow: hidden`** (at `line-height: 1` a hidden overflow clips the descender of «ё» — the symptom is the letter cut off at the bottom).
- **Header at lg (`≥64rem`):** the base grid is `auto minmax(0,1fr) auto` — the middle spacer absorbs the free space instead of reserving a fixed 22–36rem (a fixed middle squeezed the logo and the profile pill to ~180px at 1025–1256px and the logo overlapped the collab bar). The sides are content-sized, so «РепортКоллектор» keeps its natural width at any lg width and never ellipsizes.
- **Toolbar:** now only the tabs (the collab presence moved into the merged `FormStatus` footer summary — see «Footer stats block» below). Below lg the inline `FormStatus` lines («На форме: …», «Выделено: …», «Строки: …») are hidden (`.form-status__presence`/`__selection`/`__rows` `display: none`) — only the status badge (dot) remains and still opens the tooltip; the tabs take the full remaining row width and scroll internally (HeroUI arrows) when they don't fit.
- **Archive picker:** `SearchAutocomplete` got `compactLabel` («Архив») — `useMediaQuery("(width < 64rem)")` swaps the trigger text via `Autocomplete.Value` render-children; the opened popover keeps its full width. `.archive-autocomplete` is `width: auto` at **every** width — the trigger is content-sized («Рабочая версия» two lines at lg, «Архив» compact below lg) and the popover never follows it (`.search-autocomplete-popover`: `width: max(var(--trigger-width, 0px), 22rem)`). At lg the trigger shows the item name and its description («Доступна для редактирования» / fixer + date) on a second line in `text-xs text-muted` (the `selectedKey` is looked up in `items` inside the render-children).
- **Action bar:** `ActionBar` renders either the inline buttons or a single «Действия» button (`CompactActionMenu`) from the **same** `ActionItem` list (full-text items with icons, disabled states and the export split into «Скачать всю таблицу» / «Скачать видимую таблицу») — chosen by `useMediaQuery`. «Зафиксировать» gets `[&_[data-slot=label]]:text-success` on the item (HeroUI MenuItem ships only `danger`; success is reproduced the same way — the theme's `--success` token colors the **label** slot via a stock Tailwind utility, no custom CSS), the delete item `variant="danger"`; «Действия» itself uses the MoreHoriz icon. The former grid corner options menu (`GridOptionsMenu`) is **removed**: its toggles moved into the view strip (see above), and its reset action lives in the strip's reset dropdown.
- **Landmine (historical, keep avoiding):** never mount react-aria components into a Stencil shadow root via `createRoot` — the RAC collection renders into a virtual document that has no `createTextNode`, and React dies on the first text node (`getOwnerDocumentFromRootContainer(...).createTextNode is not a function`). This killed an earlier shadow-DOM-mounted corner menu; all popovers live in the regular tree.
- `HoverDropdown` (`front/src/shared/ui/hover-dropdown.tsx`): a `Dropdown` that opens on hover and closes when the pointer leaves both trigger and popover for ~250 ms. **Closing is pointer-position based (`getBoundingClientRect` polling on `pointermove`), NOT `mouseleave`** — while a modal popover is open, react-aria sets `inert` on everything outside it, the trigger stops being hit-testable, the browser fires a phantom `pointerout`, and a `mouseleave`-based close loops forever (open → inert → phantom leave → close → un-inert → re-enter → open). Escape closes in capture phase and suppresses the hover reopen until the pointer physically leaves the trigger (otherwise the closing menu un-inerts the trigger and the still-hovering pointer re-opens it instantly).
- `useMediaQuery` (`front/src/shared/hooks/use-media-query.ts`): starts `false` (SSR-safe), subscribes via `matchMedia`. **Landmine:** React implements onMouseEnter over `mouseover`/`mouseout` — dispatching synthetic `mouseenter` doesn't fire it (test hover-open with `mouseover` or real pointer events; `front/e2e/hover-dropdown.spec.ts` does exactly that with `page.mouse.move`).
- **Tiny tooltip triggers (the collab dot):** `locator.hover()` can miss an 8×8 trigger (its pointer move can land outside / get eaten), so the collab e2e opens the tooltip with an explicit `page.mouse.move` from a distance (`hoverCollabBar` in `front/e2e/collab.spec.ts`); the dot's own hit area is padded in CSS to ~18px.

## Ремонт (`front/src/features/renovation/`)

The renovation plan is a separate grid sharing the raw-materials infrastructure but with its own component (`renovation-grid.tsx`), workspace (`renovation-workspace.tsx`) and client (`front/src/shared/api/renovation.ts`, scope `RENOVATION_SECTION = "renovationPlan"`, `reportMonth = null`). Project switcher: `report-workspace.tsx` renders `RenovationWorkspace` when `activeProjectKey === "renovation"`, otherwise `RawMaterialsWorkspace`.

- **Overlay column header.** The Excel form has 11 header levels (`meta.headerRows`), which revo-grid's native header cannot render. The grid's own header is hidden and the page draws the levels itself: `.renovation-grid revogr-header { display: none !important }` hides **both** `revogr-header` elements — the main column header **and the corner header inside `revogr-row-headers`**. Both live in their own `revogr-viewport-scroll` whose `.inner-content-table` is a flex column (header + `.vertical-inner`), so hiding only one would offset its data area by the header height and misalign the «№» column with the data rows; hiding both makes both data areas start at y=0. The overlay (`.renovation-grid__header`, height 264px = 11 × 24) is positioned over the grid, tracks the horizontal scroll **imperatively** — `onViewportscroll` writes `translateX(-x)` straight onto a ref'd `.renovation-grid__header-body` (no React state per tick: a `setScrollLeft` on every scroll tick re-rendered the whole grid and made horizontal scrolling janky; the inline transform is left out of the JSX so React re-renders don't reset it), has an opaque 52px corner matching `ROW_HEADER_WIDTH` (its own box-shadow closes all four edges, including the right border over the data row headers), and per-column resize handles (pointer capture → live `overlayWidths`, committed to `localStorage["renovation:colWidth:<dbName>"]` and to the grid columns on drop). **Landmine**: the handles live in `.renovation-grid__header-body`, which is absolutely positioned with all-absolute children — it collapses to 0 height unless it gets an explicit `height: headerHeight` inline style; without it `top: 0; bottom: 0` on the handles resolves to a 0px-tall, unclickable strip. **Full-height columns with no level-0 cell above them are raised to the top** by the overlay: in the Excel «Идентификационный код работы/ремонта» (position 1) and «Примечание» (position 215) start at row 7 (level 1) with an empty level-0 slot above them (the three responsibility-block rows cover positions 2–214). The overlay computes the union of level-0 spans and lifts uncovered cells to `top: 0` with `height: (level + rowSpan) × 24` — otherwise the cell's top border sits at the blocks' bottom line ("as if it belonged to Ташпаев's block") and «Примечание» shows a spurious second top border with its right border missing in the top corner.
- **Columns** come from `meta.fields` (prop = `dbName`), widths from `localStorage`/defaults by cell type, `min/maxSize` 60–600. A synthetic **«Предприятие»** column (`__assetName`, default 220px, resizable like the plan columns — its width persists under `localStorage["renovation:colWidth:__assetName"]`) is always prepended: it shows the row's asset and is **read-only** (rows are added through the «Добавить строку» dialog, all columns are set after); its overlay header cell spans the full 264px header. The form's own `col_002` field («Предприятие») is excluded from the field columns — it duplicates the synthetic column (its header cell is dropped along with the field, `visibleIndexByPosition` shifts accordingly). Boolean columns: a toggle button template (immediate `onClick` commit, `editor` not set — same as raw's checkbox), no separate editor. Number columns render through `Intl.NumberFormat("ru-RU")` (`report-cell__number`). Read-only columns are greyed (`report-cell--readonly`); calculated columns are tinted green (`report-cell--calculated`, `--cell-calculated`) — except when the row has missing components (`__missingComponents`), i.e. the code renders `<NULL>`: then the cell is tinted red (`report-cell--invalid`, `--cell-invalid`).
- **Filters.** `blockFilter` (a responsibility block from `field.responsibilityBlock`; `col_003` and `col_217` — the renovation id and the note — are always visible, `col_002` is hidden entirely; the `read_only` block is excluded from the dropdown — it only groups hidden/always-visible columns) is applied to the columns; `assetFilter` (client-side) is applied to the rows via `displaySource`. Editing constraints: `editableFieldKeys` (approver → none; everyone else → non-calc, non-read-only) and `userAssetIds` (rows the user may edit; null for admin/approver).
- **Blocks.** The three responsibility blocks have **canonical display names** — `BLOCK_LABELS` in the workspace (`tashpaev` → «1) Блок Ташпаева», `borodiichuk` → «2) Блок Бородийчука», `babaeva` → «3) Блок Бабаева`). Both the «Все блоки» `Select` (in that order, after «Все блоки») and the level-0 column-header overlay cells (their Excel text «Блок … (раздел N)» is replaced in `overlayCells`) render these labels, so the filter and the table always agree.
- **Diff view.** A non-working version (`pendingApproval`/`archived`) is opened read-only with a diff against `diff.comparedToPlanId`: rows carry `__rowState` (`new`/`changed`/`unchanged`), changed cells are tinted, and rows deleted in the viewed version are shown as **ghosts** (`__rowState: "deleted"`, strikethrough) filled from the comparison plan by `position`. `plan.baselineBoundary` (the first row of the next baseline generation) draws a green line (`report-cell--baseline-boundary` / `report-row-header--boundary`); deletions above it are rejected by the server.
- **Clipboard.** Copy/paste are custom (capture-phase window handlers, `event.code`, `isGridTarget`, `rangeeditapply` → `beforeRangeEdit` so leases/validation/undo work uniformly), same as raw — but with **no Ctrl+X** (no cell clearing) and **no Ctrl+A** (delete is row-level). The paste button (`pasteIntoSelection` on the grid handle) is enabled when `onClipboardStateChange` reports `canPaste`.
- **Selection payload** includes `rowId` (the row the range started in) so the workspace can delete the row; row deletion uses `DeleteRecordDialog` (reused from raw). **Adding a row** is a button in the action bar (next to «Удалить строку»): it opens `AddRowDialog` with an asset `SearchAutocomplete`; on confirm the workspace calls `addRenovationRow(assetId)` (an empty row for that asset appended at the plan's end) and refreshes. There is **no in-table placeholder row** for the renovation plan — the «Предприятие» column is read-only, edits go through the dialog. The dialog lists every asset for admins/approvers and only the user's own assets for `asset_worker` (the server enforces the same).
- **Row numbering («№»).** The row header shows the **stored plan position verbatim** (`__position`), not a visible index: positions are 1-based everywhere (the Excel seed reads the «№ п/п» column; `add_row` starts at 1 and appends max+1), and the lazy window holds a contiguous slice by position, so the numbers stay stable as the window slides. Selection labels, presence payloads and the Excel export (`export.py`, column A) use the same numbers — never add 1 again. The backend test fixture seeds rows 1-based for the same reason (was 0-based via bare `enumerate`, which made the UI start at «2» on 1-based production data while tests stayed green).
- **Lazy window (working plan).** The plan holds ~94k rows, far too many for one request or for memory. The workspace keeps a **sliding window** (`WINDOW_CHUNK = 300`, `WINDOW_MAX_ROWS = 1200`) loaded through `getRenovationPlanRows(offset, limit, undefined, assetFilter)` and **anchors it at the tail**: on open (and on filter/version change) it first reads the total (limit=1) then fetches the **last** chunk, and `scrollToEdge="bottom"` scrolls the grid to the loaded end, so the newest rows are in view. The grid reports when the user gets within `LAZY_EDGE_ROWS = 90` of either edge (`hasMoreTop`/`hasMoreBottom` + `onNearTop`/`onNearBottom`, driven by a scroll+ResizeObserver on the internal strip); the workspace prepends/extends and evicts the far side, compensating the scroll by `deltaRows × 36` (`scrollCompensation`) so the viewport doesn't jump. `refresh()` reloads the current window in place (keeps the anchor); the asset filter is server-side. Column virtualization makes the grid render only what's on screen — heap stays flat through thousands of rows. Archived versions remain full reads (read-only comparisons). **Landmine:** the edge watcher must attach to the **internal `revogr-scroll-virtual.vertical`** (pinned) / `.revo-grid-vertical-scroller` (unpinned) and poll until the stencil strip exists — attaching to the external scroller in pinned mode silences it forever.
- **Undo/redo** mirror raw: `pendingCommitRef` race guard, `skipActionId`-based conflict resolution, counters refreshed from `getUndoState()` on version switch, Ctrl+Z/Ctrl+Shift+Z/Y by `event.code`.
- **Lifecycle.** `submit` (working → pendingApproval; admin or any block owner) and `approve` (pendingApproval → archived + new working copy with `baseline_generation + 1`; admin or approver) both reset the undo counters. Export is a single action (`exportRenovationPlan(planId?)` + `downloadBlob`).
- **Collab** is enabled only for the working version: room key = project, section = `renovationPlan`, `reportMonth = null`, `onRowsChanged` → refetch, remote cell values merged into `displayRows` only when not archived. Presence/leases/tooltips use the same `remoteLocks`/`remotePresence`/`remoteCellInfo` maps and the same preemption/`suppressSelectionSendRef` pattern as raw.
- **CSS** lives in `globals.css` under a `.renovation-grid` block (theme vars, cell borders, state tints, overlay, boolean button, baseline line) — the raw-materials rules are scoped to `.raw-materials-grid`, so the renovation grid gets its own copy. Keep `.dark .renovation-grid { color-scheme: dark }` if the `theme` prop changes. **Header cells paint only LEFT+BOTTOM lines** (the container paints the single top line, and each cell above paints the shared bottom edge) — a TOP line on every cell doubles the borders between the level-0 block row and what's below into 2px.
- **Pinned mode: the `min-height: 300px` landmine.** The revo-grid library stylesheet sets `revo-grid { min-height: 300px }` (a Safari stretch workaround). Under the pinned 264px overlay header the data viewport is often shorter than 300px — the grid then refuses to shrink, overflows the clipped `.grid-viewport` and the trailing rows become unreachable while the footer still shows below. `.renovation-grid { min-height: 0 }` in globals.css beats the host rule — don't remove it. (Fullscreen "fixes" it only because the toolbar/footer collapse and the viewport clears 300px.)
- **Perf: the presence echo loop.** The grid's selection effect depends on `onSelectionChange`, which the workspace recreates whenever `room` changes; `room` changes on every presence echo (the server broadcasts the sender's own update back). With a selection, each cycle sent a fresh content-equal object → `setSelection` re-rendered the whole workspace + grid → new send → … a self-sustaining loop at WebSocket-RTT speed (measured: 31 presence sends per 1.5 s idle, 61 → 20 fps horizontal scroll, button animations janking). The workspace's `handleSelectionChange` drops content-equal payloads (`lastSelectionContentRef`); without a selection `setSelection(null)` bails out, which is why the loop only existed while a cell was selected. Don't remove the guard, and keep any new selection-callback out of effect deps or guard it the same way.
