# Grid (frontend, revo-grid)

Main code: `front/src/shared/grid/` (`raw-materials-grid.tsx` — the grid component, `grid-config.ts` — forms/columns config, `grid-edit.ts` — edits, `grid-editors.tsx` — cell editors, `section-tabs.tsx` — form tabs). Orchestration: `front/src/features/raw-materials/raw-materials-workspace.tsx`.

Stack: `@revolist/react-datagrid` 4.27 (revo-grid), React 19, HeroUI (tooltips, modals, toasts), Tailwind 4, Next 16. Custom editors are registered through `revo-grid` (see `grid-editors.tsx`).

## Forms and columns (`grid-config.ts`)

- `SectionId`: `materialMovement` («Движение»), `rawMaterialPrices` («Цены»), and the dictionaries `rawMaterials`, `assets`, `deliveryBases`, `users`. `MAIN_SECTIONS` = movement+prices; dictionaries are admin-only. The `users` table shows «Время последнего входа» (`lastAuthenticatedAt` from `app_users`, read-only `datetime` column) — the last successful authentication (Keycloak or local), null until the user has logged in. The «Сбросить пароль» action column is hidden when Keycloak is enabled (passwords are managed in Keycloak) — flag flows through `GridColumnContext` into `getVisibleDescriptors`/`editableFieldKeys`/export. The profile modal hides its password-change fields the same way (it fetches `/api/auth/config` itself; if the config is unknown it keeps the fields).
- `ColumnDescriptor`: key, label, width, kind (`text|number|boolean|asset|assetsMulti|basis|datetime|calculated`), `fixed` (pinned, non-editable), `path` (nested header, e.g. «Потребность / План, т»), `adminOnly`, `exportable`, `readOnly` (editable in no row — e.g. the renovation users' `email`, which only the creation dialog sets).
- Merged headers (`ColumnGrouping`) are built from `path`; editors: `reference` (single pick from `source`), `multiAssets` (multi-pick), booleans — checkbox template.
- Each row is a `GridRow`: id, `rowState` (`unchanged|new|deleted`), `changedFields`, `isDeleted`, `canonicalCells` (canonical cell keys), `isPlaceholder` (the trailing «добавить запись» row; the users dictionaries have none). Its row-header button shows **«+» instead of a number** («Добавить строку» tooltip) — same as the renovation plan grid.
- **Users are created through a dialog, not the placeholder row.** The `users` dictionaries of both projects (and only they) create records through the shared `AddRecordModal` (`front/src/shared/ui/add-record-modal.tsx`) opened by the «Добавить пользователя» action-bar button (the same `Plus` icon as every other dictionary). The trailing placeholder row is not rendered for `users`. The modal's fields are role-dependent: in «Ремонт» the role picker drives which fields show — the «Дирекция» for `block_owner`/`asset_worker`, the «Активы» picker only for `asset_worker` (admin/approver implicitly cover every asset, so they show neither). The modal validates (email/ФИО/role/block/assets) and keeps itself open with the message on failure; a successful create refreshes the grid and offers Ctrl+Z (the server journals it like any dictionary create).
- Default sort: raw-material items first, then assets; placeholder/deleted always at the end (`placeholderLastCellCompare`).
- Form reads: «Движение» — `GET /movement?report_month=`, «Цены» — `/prices`; dictionaries — their own GETs. Edits — `PATCH /movement`, `/prices`, `updateDictionaryCells`; one edit = a batch `{rowId, field, value}`.
- **«Бизнес-план, т» in «Движение» is a projection from «Цены», non-editable; in «Цены» business-plan edits go to `RawMaterialPrice` and are not "projected" onto other forms.**

## Clipboard

`raw-materials-grid.tsx`, "clipboard" section (functions `copySelection`, `pasteIntoSelection`, `cutSelection`, `buildCopyText`).

- **Copy (Ctrl+C)** — by value: numbers as-is (`,` for decimals), multi-dictionaries — joined with `,`; the copy goes to the system clipboard (`navigator.clipboard`).
- **Paste (Ctrl+V)** — the whole path goes through `rangeeditapply` → `beforeRangeEdit`, so locks/validation and undo/redo work uniformly:
  - Dictionary fields: single dictionary — the value must match an option; multi (`assetsMulti`) — `split(",")`, **each** value `str.strip()`-looked up among options, otherwise the paste is rejected (toast). When pasting dictionary rows, values are mapped to **existing UUIDs** (by value after strip).
  - Sizes: one cell selected → paste everything starting from that cell; ≥2 cells selected → paste only into the selected range: if the pasted range is bigger — it's **trimmed** by the range (toast), if smaller — pasted as-is, other cells untouched.
  - **Excel buffer**: trim trailing empty rows and columns (Excel puts a trailing `\n`) — otherwise an extra empty cell below overwrites a neighbor.
  - **Numbers**: any Unicode whitespace is accepted as a thousands separator (regular space, NBSP, narrow NBSP — Excel uses different ones), `,` becomes `.`. Front: shared `parseNumericText` (`front/src/shared/grid/grid-edit.ts`, used by both grids); back: `coerce_number` (`raw_materials/service.py`) and the seed parser — keep them in sync.
  - After paste the selection moves to the pasted cells and goes to presence.
- **Ctrl+X** — like Ctrl+C but clears the source cells (empty value; multi — empty list; boolean fields skipped). Through the same `rangeeditapply` → busy cells are skipped, the operation lands in undo/redo.
- **Hotkeys — by `event.code`** (`KeyC/KeyV/KeyX/KeyZ/KeyY/Delete`), otherwise broken with the Russian layout. Ctrl+Z/Y — undo/redo (server-side stack, see `docs/COLLAB.md`). Ctrl+Delete — opens the delete confirmation dialog (same dialog as the action-bar button; dictionaries here, plus the renovation plan/dictionaries), active only when deletion is possible. **Undo race guard:** the workspace keeps the in-flight commit promise in `pendingCommitRef` and `runUndo`/`runRedo` await it first — a Ctrl+Z pressed right after Enter would otherwise reach the server before the PATCH journaled the edit and silently do nothing (observed as an e2e flake under load).
- The paste button («Вставить») only works when the buffer is compatible with the selection (`canPasteRange`) — also through the visible row source.

## Selection

- **Ctrl+A — fully custom**: a `document` handler in the capture phase with `stopImmediatePropagation` (kills revo-grid's built-in select-all, which draws three torn frames — header/data/bottom). Selects one contiguous range over the data cells, **without headers and without the «добавить запись» row**. The range is derived from the **visible source** (sorting/filtering applied), not the raw `rows` array. On the «Ремонт» plan Ctrl+A is disabled entirely (see below).
- **Programmatic selection — only through the grid's public API**: `grid.setCellsFocus(start, end)` + `grid.refresh()` (without `refresh` Stencil doesn't redraw the overlay). Reset — `grid.clearFocus()` + `grid.refresh()`: the store empties, but without `refresh` the old range rectangle stays visible. **`store.setRange` doesn't exist** (in `revogr-overlay-selection` there's a raw observable without methods) — it's dead code, don't use it.
- Row selection (click/shift/ctrl on the row number) **resets** the cell selection (`clearGridSelection`) — both state and the visual frame. The shift-range maps indexes through the visible source too (sorting/filtering), like everything index-based. **Order matters**: the range is cleared **before** `setSelectedRowIds` — the row selection rebuilds `columns` (selectedRowIds is a `columns` dependency) and revo-grid's `columnChanged` captures the still-live focus into `pendingColumnFocusRestore`, which `restoreColumnFocusAfterRender` then re-applies as a single-cell range (its guard can't match an empty store). `clearGridSelection` also drops the stale restore for the same reason.
- **Escape on the «Ремонт» grid additionally bumps `selectionEpoch`** (a `columns` memo dependency) **after** `clearGridSelection`: with a plain range (no row selection) `setSelectedRowIds([])` changes nothing, no columns rebuild happens, and the selection overlay does **not** reliably repaint on a bare store change — the rectangle stays until the next keypress. The forced rebuild repaints the overlay from the already-empty store (safe: `columnChanged` finds no focus to restore — same reasoning as row clicks). The «Сырьё» grids don't need it: their selected-row classes live in `rowHeaders`, not `columns`, and their overlay repaints correctly on `clearFocus` + `refresh`. Escape and the clipboard shortcuts ignore presses from inside text editors — checked via `composedPath` (`isFromTextEditor`, `front/src/shared/keyboard.ts`): revo-grid's built-in cell editors are shadow-DOM inputs, invisible to `document.activeElement`.
- A mouse-dragged selection is sent to presence **only on completion** (`setrange`), not live.

## Pinned header and scrollbars

- The «Закрепить заголовок» option (grid options menu, ⋮) is **on by default** (`headerPinned` state in `raw-materials-workspace.tsx`). The «Сырьё» grids: pinned — the grid fills the shell (`revo-grid-shell--pinned`), revo-grid scrolls internally; unpinned — an external vertical scroller plus a custom horizontal strip (`revo-grid-external-scrollbar`), the grid sized to its content (`--grid-content-height`). **The «Ремонт» plan is different**: it always fills the shell and scrolls internally (the native vertical strip; the custom external horizontal strip at the bottom); the header overlay lives in a flex slot whose `margin-top` animates to `-headerHeight` and `opacity` to 0 when unpinned (`renovation-grid__header-slot--hidden`) — the grid simply grows (revo-grid re-measures), so toggling the pin never reloads the table. The old external 11M-px vertical scroller (content height of 306k rows) was removed: with the Infinity Scroll source it froze the renderer.
- **Scrollbars are the browser's native ones, no custom styling.** revo-grid hides its raw viewport scrollbars (`scrollbar-width: none`) and renders `revogr-scroll-virtual` strips whose *own* native scrollbars are the visible bars — they're real light-DOM elements, and revo-grid sizes them to the measured system scrollbar width, so pinned and unpinned bars naturally match. **Landmine**: revo-grid's light theme sets `color-scheme: light` on the host → native scrollbars render light even in the app's dark theme; `globals.css` fixes it with `.dark .raw-materials-grid { color-scheme: dark }` — keep that override if the `theme` prop changes.
- Scrollbars appear only when there's overflow (native `overflow: auto`); `revogr-scroll-virtual` collapses to 0 size without overflow (revo-grid sets its min-size to 0 in `componentDidRender`). Without overflow the «Сырьё» external strip is hidden via `revo-grid-shell--no-hscroll` (`hasHorizontalOverflow` state) — no dead 17px gap under the last row; the plan's native horizontal strip collapses the same way (`--no-hscroll` + the forced-height rule below).
- **The plan's strips** (`renovation-grid-shell`): the native horizontal strip is **hidden** (`height: 0 !important` in both pin states — Chrome draws it too thick); the custom external strip (`revo-grid-external-scrollbar`, 17px, own webkit styling, hidden via `--no-hscroll` when everything fits) is the visible bar — its spacer carries the full content width, `onScroll` drives `grid.scrollToCoordinate`, the grid's `rgCol` viewport scroll syncs it back, and **wheel over it scrolls sideways** (JS, see below). The native vertical strip stays and starts **below the pinned summary row** (`top: var(--renovation-summary-height)`) instead of covering it. **Landmine (raw grids, unchanged):** in unpinned mode BOTH internal scrollbars are hidden there — zeroing the strip sizes (`width/height: 0 !important` + min-*), not `visibility: hidden` alone (revo-grid sets an inline min-size; Firefox paints the scrollbar of a hidden container).

## Coordinates: sorting and filtering (the most important landmine)

Under sorting/filtering the screen row index **doesn't match** the `rows` index (the source array is unsorted). Anything mapping "index → row" must use **`getVisibleRows()`** (`grid.getVisibleSource("rgRow")` — the current sorted/filtered source): paste (building `models`), cut, copy (including the context menu), presence (my selected keys), `canPasteRange`. Otherwise values are committed to the wrong row → fake asset "deletions" → RESTRICT error (symptom: «ошибка удаления актива» when pasting on a sorted sheet).

## Presence and tooltips («На форме»)

- The collab presence and the selection/filter summary are one merged component — `FormStatus` (`front/src/shared/ui/form-status.tsx`) — in the **bottom footer**, left of the action bar; the presence helpers live in `front/src/shared/collab/collab-presence.ts` (`membershipSummary`, `memberDetail`, `memberSelectionLabel`, `shortName`). Inline it is a row: the status badge (dot) on the **left, vertically centered** against the stacked lines `<b>На форме:</b> …` / `<b>Выделено:</b> …`; the HeroUI tooltip spells out «Выделено» and «Строки»/«Столбцы» first, then the member presence list. «На форме» uses last names only, **«вы» is lowercase**, role «админ» (not «Администратор»), for an asset worker — the **concrete asset list**; full FIO and cell ranges — only in the tooltip.
- **Top vs bottom panels:** the top (toolbar + view strip) holds view controls — the version picker («Рабочая версия»), tabs, the asset/block filters (renovation plan), the display toggles, the reset dropdowns and fullscreen; the bottom footer holds the presence/selection summary (`FormStatus`) and the actions — undo/redo/copy/paste/export/add/delete/submit/approve (the Excel export lives in the bar; `ViewStrip` renders with `hideExport`).
- **View strip** (`.view-strip`, between the toolbar and the grid): one row, `justify-content: space-between` — on the left the filters (only where they exist: the «Ремонт» plan gets a content-sized «Все блоки» `SearchAutocomplete`) followed by the **«Закрепить заголовок» / «Показать служебные столбцы» switches** (`.view-strip__toggles`, HeroUI `Switch` compound: `Content > Control > Thumb`), and on the right the **shared `ViewStrip`** (`front/src/shared/ui/view-strip.tsx`) controls: an Excel export dropdown («Скачать всю таблицу» / «Скачать видимую таблицу» — currently hidden in both workspaces via `hideExport`, the export lives in the footer action bar), a **reset dropdown (`variant="danger"`, its items danger too)** — «Сброс ширины столбцов» and «Сброс всех фильтров и сортировок» — and the fullscreen toggle (`variant="tertiary"`). All three, plus the compact «Действия»/«Таблица» menus and the `AppHeader` project switcher, open on **hover** (`HoverDropdown`); the action bars default to `variant="tertiary"` (`action.variant ?? "tertiary"`). While a hover dropdown is open, react-aria inerts the rest of the page, which drops the trigger's `:hover` and collapses its label — so `HoverDropdown` passes `isOpen` to the trigger and the view-strip export/reset buttons add an `action-button--open` class (kept label/gap) for the duration. The toggles are fully controlled: both grids take `headerPinned`/`showServiceColumns` props, state lives in the workspaces (raw: one pair for all sections; renovation: separate pairs for the plan and dictionaries). The service columns are the SAME audit trio everywhere (`SERVICE_DESCRIPTORS` in `grid-config.ts`): «Время добавления» (`createdAt`), «Время редактирования» (`updatedAt`) and «Автор последней редакции» (`updatedBy`). The plan grid derives its service columns from that shared list, so it no longer shows the internal id/position/revision; `createdAt` was added to `RenovationPlanRowRead` for it. **Below md (< 48rem)** the switches and all right-side controls collapse into one hover menu («Настройки таблицы», MoreVert trigger) whose entries carry a leading check for active toggles. **Responsive sizing:** HeroUI's theme ships sm:/md: variants that resize controls across breakpoints; globals.css freezes --breakpoint-sm/--breakpoint-md to 0rem in @theme, so every component renders its roomier base look at all viewports (the app itself uses no sm:/md: utilities). Don't reintroduce custom per-breakpoint size pins for chrome controls. «Видимая таблица» exports the rows the filters keep: raw passes `getExportState().rowIds`; the renovation plan POSTs `/plan/export {planId?, asset?, block?}` — the **server-side** equivalent of the on-screen filter (the whole plan narrowed by asset and responsibility block, not just the loaded window); renovation dictionaries pass `state.rowIds`. `rowIds` remains the exact-set form (an explicit selection). Reset wiring: grids expose `resetColumnWidths()`/`resetFiltersSorting()` on their handles (raw clears its in-memory width map + bumps `widthsVersion`; renovation clears its localStorage `renovation:colWidth:*` keys; filters/sorting = plugin clear + `clearSorting`, for the plan grid = workspace asset/block **and header** filter reset); sections register them upward via the `onResetState` callback (the same pattern as `onExportState`). In fullscreen the in-flow strip collapses to zero height together with the toolbar/footer (`max-height: 0`) so the grid reclaims the viewport, while the same JSX renders on the floating top panel. **Fullscreen panels are shared state** (`front/src/shared/ui/use-fullscreen-panels.ts`): the hook owns the fullscreen/pending state, the pointer-over-panel check and the open state, and returns the reveal className. Every control that opens a portaled menu (toolbar autocompletes, the view strip, the action bar / download menu, the compact action menu) reports `onOpenChange`→`setToolbarControlOpen`; otherwise react-aria's `inert` drops the panel `:hover` and the panels would hide mid-interaction — the hook keeps them open on **both** projects identically, and both panels may show at once.
- **Action bar grouping:** consecutive `ActionItem`s sharing `group` render joined in one HeroUI `ButtonGroup` (`groupActionItems` in the shared `front/src/shared/ui/action-bar.tsx`): undo+redo share `"history"`, copy+paste share `"clipboard"`. The compact «Действия» menu stays flat.
- **One account in several tabs** — the backend keeps one presence entry per user, so the tabs share it ("last writer wins"): when a `presence:update` arrives where my user's selection differs from what this client last sent (another tab took over), the local grid selection is cleared **silently** (`onSelectionPreempted` in `ws-client.ts` → the workspace clears the grid via the `clearSelection` handle; the resulting empty presence send is swallowed by `suppressSelectionSendRef` in `SectionContent` — otherwise the tabs would clear each other in a loop). The stale `lastSelection` is dropped so a reconnect doesn't resurrect it.
- **Tooltips — HeroUI `Tooltip`, not native** (for presence and busy cells; positioning reference — ReportCollector-RawMaterials). In the tooltip: full FIO as an unordered list, role/assets in parentheses, the cell range under the FIO in normal (not bold) font, the column name in quotes («Потребность / План, т»). `white-space: nowrap` + `max-width: none` — no word wrapping («Земелькин Сергей Александров\nич» is unacceptable).
- Yellow highlight of cells occupied by others (completed selection) with a "FIO — range" tooltip.
- In the archive «Движение» / «Ремонт» version presence isn't maintained — «На форме» isn't shown at all (`FormStatus` gets `room={null}`).

## Responsive layout (below lg, `@media (width < 64rem)`)

A split-screen tab (≈ half a desktop) triggers the compact shell; one `@media (width < 64rem)` block in `globals.css` plus two components (`raw-materials-workspace.tsx`):

- **Header:** the middle spacer column is dropped (`grid-template-columns: minmax(0,1fr) minmax(0,auto)`, spacer `display: none`); «РепортКоллектор» may ellipsize, «Сырьё» never does — and keeps `line-height: 1.2` with **no `overflow: hidden`** (at `line-height: 1` a hidden overflow clips the descender of «ё» — the symptom is the letter cut off at the bottom).
- **Header at lg (`≥64rem`):** the base grid is `auto minmax(0,1fr) auto` — the middle spacer absorbs the free space instead of reserving a fixed 22–36rem (a fixed middle squeezed the logo and the profile pill to ~180px at 1025–1256px and the logo overlapped the collab bar). The sides are content-sized, so «РепортКоллектор» keeps its natural width at any lg width and never ellipsizes.
- **Toolbar:** now only the tabs (the collab presence moved into the merged `FormStatus` footer summary — see «Footer stats block» below). Below lg the inline `FormStatus` lines («На форме: …», «Выделено: …», «Строки: …») are hidden (`.form-status__presence`/`__selection`/`__rows` `display: none`) — only the status badge (dot) remains and still opens the tooltip; the tabs take the full remaining row width and scroll internally (HeroUI arrows) when they don't fit.
- **Archive picker:** `SearchAutocomplete` got `compactLabel` («Версия») — `useMediaQuery("(width < 64rem)")` swaps the trigger text via `Autocomplete.Value` render-children; the opened popover keeps its full width. `.archive-autocomplete` is `width: auto` at **every** width — the trigger is content-sized («Рабочая версия» two lines at lg, «Версия» compact below lg) and the popover never follows it (`.search-autocomplete-popover`: `width: max(var(--trigger-width, 0px), 22rem)`). At lg the trigger shows the item name and its description («Доступна для редактирования» / fixer + date) on a second line in `text-xs text-muted` (the `selectedKey` is looked up in `items` inside the render-children).
- **Action bar:** the shared `front/src/shared/ui/action-bar.tsx` owns the rendering — `ActionBar` renders either the inline buttons or a single «Действия» button (`CompactActionMenu`) from the **same** `ActionItem` list — while each workspace only builds its own ordered `ActionItem[]` (full-text items with icons, disabled states and the export split into «Скачать всю таблицу» / «Скачать видимую таблицу») — chosen by `useMediaQuery`. «Зафиксировать» gets `[&_[data-slot=label]]:text-success` on the item (HeroUI MenuItem ships only `danger`; success is reproduced the same way — the theme's `--success` token colors the **label** slot via a stock Tailwind utility, no custom CSS), the delete item `variant="danger"`; «Действия» itself uses the MoreHoriz icon. The former grid corner options menu (`GridOptionsMenu`) is **removed**: its toggles moved into the view strip (see above), and its reset action lives in the strip's reset dropdown.
- **Landmine (historical, keep avoiding):** never mount react-aria components into a Stencil shadow root via `createRoot` — the RAC collection renders into a virtual document that has no `createTextNode`, and React dies on the first text node (`getOwnerDocumentFromRootContainer(...).createTextNode is not a function`). This killed an earlier shadow-DOM-mounted corner menu; all popovers live in the regular tree.
- `HoverDropdown` (`front/src/shared/ui/hover-dropdown.tsx`): a `Dropdown` that opens on hover **and on press** (click/Enter/Space — keyboard and touch access) and closes when the pointer leaves both trigger and popover for ~250 ms. Press is open-only: on touch the synthetic mouseenter has already opened the menu, a toggle would close it instantly; and the pointer-out close only arms after a real pointermove, so a keyboard-opened menu is never killed by a stale pointer position. **Closing is pointer-position based (`getBoundingClientRect` polling on `pointermove`), NOT `mouseleave`** — while a modal popover is open, react-aria sets `inert` on everything outside it, the trigger stops being hit-testable, the browser fires a phantom `pointerout`, and a `mouseleave`-based close loops forever (open → inert → phantom leave → close → un-inert → re-enter → open). Escape closes in capture phase and suppresses the hover reopen until the pointer physically leaves the trigger (otherwise the closing menu un-inerts the trigger and the still-hovering pointer re-opens it instantly).
- `useMediaQuery` (`front/src/shared/hooks/use-media-query.ts`): starts `false` (SSR-safe), subscribes via `matchMedia`. **Landmine:** React implements onMouseEnter over `mouseover`/`mouseout` — dispatching synthetic `mouseenter` doesn't fire it (test hover-open with `mouseover` or real pointer events; `front/e2e/hover-dropdown.spec.ts` does exactly that with `page.mouse.move`).
- **Tiny tooltip triggers (the collab dot):** `locator.hover()` can miss an 8×8 trigger (its pointer move can land outside / get eaten), so the collab e2e opens the tooltip with an explicit `page.mouse.move` from a distance (`hoverCollabBar` in `front/e2e/collab.spec.ts`); the dot's own hit area is padded in CSS to ~18px.

## Status summary and view strip

- The **footer summary** (`FormStatus` — `.form-status`, one row): the **status badge** (dot) on the left, vertically centered against the stacked lines — **`<b>На форме:</b> …`** presence line, then **`<b>Выделено:</b> …`** (only when there's a selection — e.g. «Потребность / План, т», строки 3–5; row selection → «строки 3–5»), then **`<b>Строки:</b> X найдено, Y всего`** only when filters are applied (X = rows matching the current filters — `getVisibleSource` after filtering, not the viewport count; Y = total non-placeholder rows).
- The **full breakdown is in a HeroUI Tooltip on hover** over that label (`.form-status-tooltip` → `.form-status-detail`): the **member presence list** («На форме», full FIO + role/assets + cell range) — **the current user is excluded** (their own selection is shown separately below) — then «Выделено» (if any), then **`<b>Столбцы:</b> k неизменяемых + n расчётных + x заполняемых = … всего`** (from `ColumnDescriptor`: `fixed` non-`calculated` / `kind === "calculated"` / the rest; all three bold), and «Строки» when filters are applied. The detail column has a uniform gap between blocks; the presence block carries no top margin/border so the tooltip doesn't start with a stray empty line.
- Stats come from `GridViewStats` (grid → `onViewStatsChange`): `totalRows`, `filteredRows`, `totalCols`, `filtersApplied`, `immutableCols`, `calculatedCols`, `editableCols`. `filtersApplied` is read from the `beforefilterapply` event's `collection` (empty → cleared). Re-measured on `aftersourceset`/`viewportscroll`/`columnresize`, and on `beforefilterapply` (setTimeout 0 — revo-grid has no public after-filter event; filtering trims the data store synchronously). The selection label is the `onSelectionChange` payload, reported straight from the grid to the workspace (`onSelectionLabelChange`) — no presence echo needed, so it works offline.
- **Ремонт footer order:** the `FormStatus` summary, then the action bar (undo/redo/copy/paste/export/add/delete/submit/approve — fullscreen stays on the view strip; the version picker lives in the toolbar). The form selection is the same `SectionTabs` strip as «Сырьё»: «Пообъектный план» first, then the reference dictionaries after a `Tabs.Separator` (enterprises, the five catalogs, users) — a single-section (non-admin) user gets no strip. It sits **after** the version picker and the «Блок» filter; those two stay mounted and collapse (width + margin + opacity) when the section changes, so the toolbar settles instead of popping. The «Все блоки» filter is a content-sized `SearchAutocomplete` (variant secondary, the same `.search-autocomplete-popover`; a raw HeroUI `Select` double-opened here); the asset filter is a normal column-header filter on «Предприятие», not a toolbar control.

## Misc

- **revo-grid 4.27 event shapes:** plain `afteredit` carries a `data` key even for single-cell edits — the whole source snapshot as an ARRAY; a range save carries a keyed patch object plus `models` and no `prop`. `extractEdits` (both `grid-edit.ts` and the renovation grid) keys off that shape — `data` presence alone is not a range-save marker, and getting it wrong silently drops every cell edit (the grid shows the new value locally, the server never hears about it).
- **Ctrl+V goes through the native paste event** (the window `paste` listener): the keydown handlers don't intercept it, so Chrome's clipboard-read confirmation prompt never appears. The «Вставить» button still reads via `navigator.clipboard.readText()` — a one-time permission prompt is possible there.
- Changes apply live: `cell:changed` from the room updates rows (see `use-collab-room.ts`).
- Excel export — `POST /export` (openpyxl, see `export.ts` and `back/src/raw_materials/export.py`).
- Front unit tests: `front/src/shared/grid/__tests__/` (`grid-clipboard.test.ts`, `grid-export.test.ts`), run — `bun test` (happy-dom).

## Ремонт (`front/src/features/renovation/`)

The renovation plan is a separate grid sharing the raw-materials infrastructure but with its own component (`renovation-grid.tsx`), workspace (`renovation-workspace.tsx`) and client (`front/src/shared/api/renovation.ts`, scope `RENOVATION_SECTION = "renovationPlan"`, `reportMonth = null`). Project switcher: `report-workspace.tsx` renders `RenovationWorkspace` when `activeProjectKey === "renovation"`, otherwise `RawMaterialsWorkspace`.

- **Overlay column header.** The Excel form has 11 header levels (`meta.headerRows`), which revo-grid's native header cannot render. The grid's own header is hidden and the page draws the levels itself: `.renovation-grid revogr-header { display: none !important }` hides **both** `revogr-header` elements — the main column header **and the corner header inside `revogr-row-headers`**. Both live in their own `revogr-viewport-scroll` whose `.inner-content-table` is a flex column (header + `.vertical-inner`), so hiding only one would offset its data area by the header height and misalign the «№» column with the data rows; hiding both makes both data areas start at y=0. The overlay (`.renovation-grid__header`, height 288px = 11 × 24 header levels + the 24px column-number strip) is positioned over the grid, tracks the horizontal scroll **imperatively** — `onViewportscroll` writes `translateX(-x)` straight onto a ref'd `.renovation-grid__header-body` (no React state per tick: a `setScrollLeft` on every scroll tick re-rendered the whole grid and made horizontal scrolling janky; the inline transform is left out of the JSX so React re-renders don't reset it), has an opaque 52px corner matching `ROW_HEADER_WIDTH` (its own box-shadow closes all four edges, including the right border over the data row headers), and per-column resize handles (pointer capture → live `overlayWidths`, committed to `localStorage["renovation:colWidth:<dbName>"]` and to the grid columns on drop). **Landmine**: the handles live in `.renovation-grid__header-body`, which is absolutely positioned with all-absolute children — it collapses to 0 height unless it gets an explicit `height: headerHeight` inline style; without it `top: 0; bottom: 0` on the handles resolves to a 0px-tall, unclickable strip. **Full-height columns with no level-0 cell above them are raised to the top** by the overlay: in the Excel «Идентификационный код работы/ремонта» (position 1) and «Примечание» (position 215) start at row 7 (level 1) with an empty level-0 slot above them (the three responsibility-block rows cover positions 2–214). The overlay computes the union of level-0 spans and lifts uncovered cells to `top: 0` with `height: (level + rowSpan) × 24` — otherwise the cell's top border sits at the blocks' bottom line ("as if it belonged to its own top (Техническая дирекция) block") and «Примечание» shows a spurious second top border with its right border missing in the top corner.
- **Column-number strip.** Under the 11 levels the overlay draws the source workbook's helper row 2: a 24px muted strip (`renovation-grid__number-cell`) carrying each visible column's form ordinal (`meta.fields[].ordinal` — «Предприятие» = 2 … `col_218` = 218; the row-number «№» column is 1), directly above the pinned totals row. It slides with the header (the same `headerBody` translate), resizes with the columns and stays empty for the service columns. The bottom-most header cells drop their bottom line (`renovation-grid__header-cell--bottom`) so the strip's top line is the only border between them.
- **Columns** come from `meta.fields` (prop = `dbName`), widths from `localStorage`/defaults by cell type, `min/maxSize` 60–600. A synthetic **«Предприятие»** column (`__assetName`, default 220px, resizable like the plan columns — its width persists under `localStorage["renovation:colWidth:__assetName"]`) is always prepended: it shows the row's asset and is **read-only** (rows are added through the «Добавить строку» dialog, all columns are set after); its overlay header cell spans all 11 header levels (264px). The form's own `col_002` field («Предприятие») is excluded from the field columns — it duplicates the synthetic column (its header cell is dropped along with the field, `visibleIndexByPosition` shifts accordingly). Boolean columns: a toggle button template (immediate `onClick` commit, `editor` not set — same as raw's checkbox), no separate editor. Number columns render through `Intl.NumberFormat("ru-RU")` (`report-cell__number`). Read-only columns are greyed (`report-cell--readonly`); calculated columns are tinted green (`report-cell--calculated`, `--cell-calculated`) — except when the row has missing components (`__missingComponents`), i.e. the code renders `<NULL>`: then the cell is tinted red (`report-cell--invalid`, `--cell-invalid`).
- **Filters.** `blockFilter` (a responsibility block from `field.responsibilityBlock`; `col_003` and `col_217` — the renovation id and the note — are always visible, `col_002` is hidden entirely; the `read_only` block is excluded from the dropdown — it only groups hidden/always-visible columns) is applied to the columns; `assetFilter` (client-side) is applied to the rows via `displaySource`. Editing constraints: `editableFieldKeys` (approver → none; everyone else → non-calc, non-read-only) and `userAssetIds` (rows the user may edit; null for admin/approver). Row creation is narrower still — only an admin or a tech-block asset worker on its assets (see «Selection payload»); the approver's row/history/clipboard actions are removed entirely.
- **Blocks.** The three responsibility blocks have **canonical display names** — `BLOCK_LABELS` in the workspace (`tech` → «1) Техническая дирекция», `ksir` → «2) Дирекция КСиР`, `mto` → «3) Дирекция МТО`). Both the «Все блоки» filter (in that order, after «Все блоки») and the level-0 column-header overlay cells (their Excel text «Блок … (раздел N)» is replaced in `overlayCells`) render these labels, so the filter and the table always agree.
- **Diff view.** A non-working version (`pendingApproval`/`archived`) is opened read-only with a diff against `diff.comparedToPlanId`: rows carry `__rowState` (`new`/`changed`/`unchanged`), changed cells are tinted, and rows deleted in the viewed version are shown as **ghosts** (`__rowState: "deleted"`, strikethrough) filled from the comparison plan by `position`. `plan.baselineBoundary` (the first row of the next baseline generation) draws a green line (`report-cell--baseline-boundary` / `report-row-header--boundary`); deletions above it are rejected by the server.
- **Clipboard.** Copy/paste are custom (capture-phase window handlers, `event.code`, `isGridTarget`, `rangeeditapply` → `beforeRangeEdit` so leases/validation/undo work uniformly), same as raw — but with **no Ctrl+X** (no cell clearing) and **Ctrl+A fully disabled**: the plan holds ~94k rows and a whole-form copy would overflow the clipboard, so the key is swallowed (revo-grid's built-in select-all included). Delete is row-level; Ctrl+Delete opens the same delete dialog as the button. The paste button is enabled when `onClipboardStateChange` reports `canPaste` — true only when the selection contains at least one editable, non-busy target cell (`cellAllowed` + `remoteLocks`/`remotePresence`, the same rule as the raw `canPasteRange`); the workspace does not override it. Select-all is swallowed even when programmatic selection leaves focus on body before React observes the range; text-editor Ctrl+A remains native.
- **Selection payload** includes `rowId` (the row the range started in) so the workspace can delete the row; row deletion uses `DeleteRecordDialog` (reused from raw). **Adding a row** is a button in the action bar (next to «Удалить строку»): it opens `AddRowDialog` with an asset `SearchAutocomplete`; on confirm the workspace calls `addRenovationRow(assetId)` (an empty row for that asset appended at the plan's end) and refreshes. **Only administrators and asset workers of the Техническая дирекция (tech) block may add rows** — other directorates' workers, block owners and approvers get `403` (`_ERR_ADD_PERMISSION`); the server enforces it, the front hides the button for those roles. The approver (a role that cannot edit the plan at all) also gets the **add/delete/undo/redo/paste** actions removed (not disabled) and their keyboard shortcuts (Ctrl+Z/Y hotkeys and the grid paste handler) are inert; copy stays. There is **no in-table placeholder row** for the renovation plan — the «Предприятие» column is read-only, edits go through the dialog. The dialog lists every asset for admins and only the user's own assets for `asset_worker` (the server enforces the same).
- **Row numbering («№»).** The row header shows the **sequential number in the current filtered scope** (`rowIndex + 1`, 1-based): after filtering the rows are numbered 1..N anew. The stored plan position (`__position`) is NOT displayed anymore — it stays only for the **baseline-boundary** line in the diff view (`baselineBoundary` is a stored position). The remote source is index-addressed by the filtered offset, so the visible number, the grid row index and the server's page offset all agree. Selection labels and presence use the same sequential numbers. The Excel export (`export.py`, column A) still writes the stored plan positions — it is a server-side full-plan document, not the on-screen view. The backend test fixture seeds rows 1-based (was 0-based via bare `enumerate`, which made the UI start at «2» on 1-based production data while tests stayed green).
- **Remote rows (RevoGrid Pro `InfinityScrollPlugin`).** The plan holds ~306k rows, far too many for one request or memory. The grid is registered with `plugins={[InfinityScrollPlugin]}` (package `@revolist/rv-pro-trial`, trial registry in `front/bunfig.toml`) and configured through `infinityScroll` (`chunkSize 100`, `bufferSize 400`, `preloadThreshold 0.5`, `total`, `loadData`). The plugin **owns the source**: a sparse array of `total` slots that it fills/evicts chunk by chunk as the user scrolls — the workspace no longer keeps a sliding window, it only reads the scope head (`total`, `totalAll`, `baselineBoundary`) and supplies `loadRows(offset, limit)` (one `GET /plan/rows` page, server-side filtered). A row's grid index equals its offset in the filtered plan, so `scrollToRow(position - 1)` targets a «№» exactly. The config is rebuilt on `[scopeKey, totalRows]`; `scopeKey` (`renovationGridScopeKey`) identifies plan + asset + header filters — a new object makes the plugin reload from the first chunk on a version/filter switch. **Why the old flicker is gone:** the previous implementation replaced the `source` prop on every chunk, which ran revo-grid's `ViewportStore.setViewport({ realCount })` — it drops the visible item list (`items: []`) and the data band went white for frames. The plugin patches its sparse source in place, so the viewport is never reset. Live updates (edits, undo, remote cells, diff states) go through `rowPatches` — `{index, fields}` — applied with `getSourceStore('rgRow')` + `setSourceByPhysicalIndex(store, patches, false)` + `grid.refresh('rgRow')`; the workspace mirrors the same row objects (`onLoadedRowsChange` → `handleLoadedRowsChange`) and mutates them in place, never replacing the source. **The mirror is refreshed on `scrollchange`** (debounced 300 ms): the plugin loads/evicts chunks by patching its store directly and does **not** emit `aftersourceset` for them, so an `aftersourceset`-only listener left the mirror stale after the first chunk — selection labels, row shift-select and live patches silently lost every later row. The grid also keeps `rowsByIndex` (grid index → row, from `__index`) for selection/clipboard mapping: the source is sparse, so a compact array cannot be indexed by the grid's rowIndex. **Landmines:** (1) unloaded slots are `{}` placeholders, not rows — every `cellProperties`/`rowHeaders`/`editableCell` access must tolerate `__id === undefined` (`row.__missingComponents?.length ?? 0`, no row-number button, `editableCell` returns false; a missing guard crashed on `__missingComponents.length` and blanked the whole grid); (2) the **initial tail jump**: the working plan opens at its tail (rows are appended at the end) and the archive reads top-down — `scrollToPosition` is set from the scope head and the grid calls `scrollToRow(total - 1)`, but a single call is often swallowed (the grid is still settling), so the shared `jumpToRow` helper retries every 150 ms until the viewport lands within ±5 rows of the target (≤50 attempts) and is reused by the «go to row» popover; the jump is cleared (`null`) for the archive and for non-plan sections, otherwise the previous working-plan position leaks into the archive (the effect keys on `totalRows`, which changes between versions); (3) deleted-row ghosts from the diff cannot be spliced into the remote source (it is index-addressed), so deletions are reported through the diff cell highlighting only. `refresh()` patches the loaded window in place; the asset filter is server-side; the diff view still renders ghosts from `GET /plan/diff`.
- **Pinned row must always be assigned.** `pinnedTopSource` is ALWAYS passed to `<revo-grid>` — `pinnedTopSource ?? EMPTY_PINNED_SOURCE` (module-level stable empty array), never a conditional spread and never a fresh `[]`. The React wrapper only writes props it receives: omitting the prop when a section has no summary left the previous section's pinned row on the element — after visiting «Предприятия» every other dictionary showed a blank pinned strip. A fresh `[]` per render is the opposite landmine: Stencil's `@Watch` fires on every reference change and reprocesses the pinned strip. The plan grid and the shared `RawMaterialsGrid` (dictionaries) both follow the always-assigned pattern; the plan's summary values come from the server aggregate over the whole filtered scope (`GET /plan/summary`), the assets tab sums its fully-loaded rows client-side.
- **Header column filters (server-side).** Every leaf header cell of the plan grid carries a small funnel (`.renovation-grid__filter-button`, the cell must have `colSpan === 1` — group headers have no single column); an active column shows it highlighted. The funnel mirrors RevoGrid's own header filter button — the same 64×64 glyph, the same collapse/expand (width 0 → 24px on hover/focus, the label reserving the 24px, touch pointers pinning it open) and the same active color — so the plan's server-side funnels read like the client-side ones on the other grids. Clicking opens `ColumnFilterPopover` (`front/src/shared/ui/column-filter-popover.tsx`) — a **HeroUI multi-select `Autocomplete`** (no custom checkboxes): its trigger is an invisible zero-height anchor positioned at the cell rect, and the popover holds a `SearchField` plus a `ListBox` whose items are «Выбрать все (N)» (a sentinel master key; N = the distinct-value count from `facets.total`), «Пустые» (a sentinel NULL bucket, only when the column has one), then the column's distinct values alphabetically. Values come from `GET /api/renovation/plan/facets?column=&plan_id=&state=&asset=&offset=&limit=` — the whole filtered plan, paged like the rows; the search narrows the loaded set client-side. The master is **stateful, but mirrors the extremes**: it stays checked while some values are removed (so «всё, кроме некоторых» works), unchecking it clears every option — «Пустые» included — and re-checking restores them; unchecking the **last** remaining option unchecks the master, and selecting **everything** again checks it back — so «nothing selected» never keeps a checked «Выбрать все». **Landmine:** the `NULL_KEY` sentinel is only put into the selection when the column actually renders «Пустые» (`includeNulls && hasNulls`). react-aria keeps selection keys it can't match to an item, so a column without a null bucket (the two-bucket ID filter for `col_003`) would otherwise carry a phantom `__null__` in `onChange`, making the popover think a bucket is still kept and the master would never auto-uncheck. The applied filter also normalizes `includeNulls` to `includeNulls && hasNulls`, so the flag never leaks into the request for a column with no empty bucket. A HeroUI `Separator` divides the pinned options from the value list, placed after «Пустые» (or after «Выбрать все» when the column has no null bucket, e.g. the two-bucket ID filter). Filters **apply when the popover closes** (outside press / Escape), and every active column filter is sent to `GET /plan/rows` as a `filters` JSON array (`[{column, values, includeNulls}]`) — combined with AND in SQL, so the row window, the «Найдено» counter and the export all respect them. A column keeping every value drops its filter; a column keeping nothing selects no rows (never all). «Сброс всех фильтров и сортировок» clears the header filters together with the asset/block filters. Service columns have no filter. **Go to row («№»)** — the same hover funnel, drawn on the «№» **corner** cell (`renovation-grid__corner`), opens `RowGoToFilter` (`front/src/shared/ui/row-go-to-filter.tsx`) instead of the value-list Autocomplete: an anchored `Popover` with a single `NumberField` (min 1, max = the filtered total) for the sequential number. The jump happens when the popover closes (outside press / Escape) via the grid handle's `scrollToPosition` (the shared retrying `jumpToRow`); an empty field closes without a jump and an out-of-range value is clamped to [1, total]. There is **no server-side «№» range filter** anymore (the backend still accepts `position_from`/`position_to` on `/plan/rows` and `/plan/summary` for compatibility, but the front never sends them).
- **Pinned summary row.** A totals band (`renovation-grid__summary-cell`) — a 36px revo-grid pinned top row — sits right under the overlay (the header levels plus the column-number strip) and follows the horizontal scroll with the header. Each additive numeric field shows the sum over the **same scope as the remote rows** (asset + header + row-number filters), fetched from `GET /plan/summary` (`read_plan_summary` → one `SUM()` per numeric column) whenever those filters change; non-numeric fields stay empty. **Non-additive fields are excluded server-side** (`_SUMMARY_EXCLUDED_FIELDS`): the defect-statement number (`col_023`), «Продолжительность, дни» (`col_026`), both «Физические объемы работ» columns (`col_083`/`col_084`) and the whole «Статус готовности МТР к проведению ремонта» block (`col_208`–`col_211`, `col_214`) — their summary cells stay empty. Every cell keeps all four borders (the row reads as a bordered strip); a non-empty total is tinted like the calculated columns (`--cell-calculated`). The totals are the stored values, so they match what the grid shows.
- **«Предприятия» dictionary.** The descriptors (`grid-config.ts` → `renovationAssets`) put **«Число ремонтных работ»** (`repairCount`, computed server-side — the working plan's row count per asset) right before «Стоимость итого, руб. без НДС» (`totalCost`, the sum of `col_031`). Both are fixed/calculated columns and both are exported (the server's assets `ALLOWED_KEYS` mirrors them). The tab's pinned totals row sums both.

- **The «Идентификационный код» filter is two buckets, not a value list.** Every renovation ID is unique, so `col_003` offers exactly «Корректные»/«Некорректные» (`GET /plan/facets?column=col_003` returns those two, `hasNulls=false`). «Некорректные» = an empty ID or one containing the `<NULL>` placeholder that `_safe_renovation_id` substitutes for a missing component (no date / repair code / direction code); the condition is evaluated in SQL (`_renovation_id_is_correct_condition`), so it filters the window and the export without running the Python ID generator.
- **Undo/redo** mirror raw: `pendingCommitRef` race guard, `skipActionId`-based conflict resolution, counters refreshed from `getUndoState()` on version switch, Ctrl+Z/Ctrl+Shift+Z/Y by `event.code`.
- **Lifecycle.** `submit` (working → pendingApproval; admin or any block owner) and `approve` (pendingApproval → archived + new working copy with `baseline_generation + 1`; admin or approver) both reset the undo counters. `submit` first drops the empty drafts, then refuses with `409` while any remaining row's work ID (`col_003`) is incomplete or duplicated — the plan is sent for approval only when every ID is correct and unique; the message names the counts and the first offending row numbers, and the front shows it in a `SubmitBlockedDialog` AlertDialog instead of a toast. **Editing a work-ID input rebuilds `col_003`** (`_RENOVATION_ID_INPUT_FIELDS`: `col_011`/`col_016`/`col_017`/`col_018`/`col_023`/`col_024`/`col_136`/`col_189`), while an unrelated edit keeps the stored id (`existing_id` wins). The ID format follows the specification (`docs/seed/id_spec.docx`): `Год_ДО_КодНаправления_КодОбъекта[_ДопНумерация]` — the direction component has **no trailing dot**, the typical-DV two-digit suffix is appended **only when present**, and the object code is the project code (`col_136`) for improvement projects, the seven-digit defect number (`col_023`) when the DV exists, or — **without a DV** — the spec's composite `Технологическая позиция*Вид работ*Месяц начала` (`col_011*col_018*col_024`, work type abbreviated; missing parts as `<NULL>`). The «Корректировка» (`col_218`) was removed from the form (hidden in `form_schema.HIDDEN_FIELDS`, dropped from the DB by `0007_drop_plan_correction`) and is **not** part of the ID. The defect number is stored as a number, so a dropped leading zero is restored when the id is built (`706179` → `0706179`) — otherwise the 7-digit rule would reject every short defect number (e.g. the БСЗ rows). Export is a single action in the action bar (`createRenovationExportJob` → poll `getRenovationExportJob` with a progress toast → `downloadRenovationExportJob` + `downloadBlob`); the backend runs it as a **background job** (see `docs/ARCHITECTURE.md`, «Renovation plan export jobs») because the full plan is minutes of CPU: the legacy synchronous streaming endpoints still exist but the UI never blocks on them. In Chromium the flow uses the **File System Access API** (`front/src/shared/file-save.ts`): the save dialog opens immediately after the job is created (like a normal big download), then the ready file is streamed into the chosen handle — the toast shows the generation percentage (rows) first and the byte percentage (MB) while saving; a cancelled dialog stops silently, other browsers fall back to the blob download. The worker streams rows through a server-side cursor in batches and writes the workbook incrementally (formula materialization and XML serialization off the event loop); column letters and Excel formula templates are compiled once per export, and the sheet entry opts into ZIP64 (the XML exceeds 4 GB uncompressed). **Export file name** follows the other forms: `Пообъектный план — {рабочая версия | версия на согласовании | утверждённая версия} (дд.мм.гггг, чч.мм.сс).xlsx`. The timestamp is the version's freeze moment — for a pending/archived version the plan `updated_at` (submit/approve time), for the working one the **latest row edit** (`max(row.updated_at)`, computed server-side, since cell edits bump the row stamp but not the plan stamp). The backend sends the name RFC 5987 (`filename*=UTF-8''…`) so the Cyrillic name survives; the frontend decodes `filename*` (falling back to `filename`). **«Скачать видимую таблицу»** of the object plan applies both filters **server-side**: rows are narrowed to the selected asset and the workbook **columns** are trimmed to the selected responsibility block (`tech`/`ksir`/`mto` — plus the always-visible `col_002`, `col_003`, `col_217`), compacting the surviving columns to consecutive Excel columns and re-clipping the merged header ranges to match. With no filter the sheet keeps the full legacy 218-column layout minus the hidden `col_218`. **Calculated columns are recomputed at export** (`formula_engine().materialize`), so derived fields («Продолжительность, дни» = `col_026` = `col_025 − col_024`, date shifts, sums) are present even when the stored cell is NULL — an adopted/imported row may never have run the on-edit recalculation. Every header cell of a merged range carries the bordered style (not only the top-left anchor) so Excel draws the full grid frame.
- **Collab** is enabled only for the working version: room key = project, section = `renovationPlan`, `reportMonth = null`, `onRowsChanged` → refetch, remote cell values patched into the **loaded rows** only when not archived (the remote source holds only a window, so a value for an unloaded row is picked up when its chunk loads). The patch covers **calculated** fields too (formula results + `col_003`): the backend publishes them as `cell:changed`, and the workspace applies them to the mirrored row objects — for `col_003` it also refreshes `__renovationId` and derives `__missingComponents` from the `<NULL>` placeholder in the value. Presence/leases/tooltips use the same `remoteLocks`/`remotePresence`/`remoteCellInfo` maps — now the shared `useRemoteCellMaps` hook (`front/src/shared/collab/use-remote-cell-maps.ts`), content-stabilized so a presence heartbeat with unchanged state doesn't rebuild the columns memo — and the same preemption/`suppressSelectionSendRef` pattern as raw.
- **CSS** lives in `globals.css` under a `.renovation-grid` block (theme vars, cell borders, state tints, overlay, boolean button, baseline line) — the raw-materials rules are scoped to `.raw-materials-grid`, so the renovation grid gets its own copy. Keep `.dark .renovation-grid { color-scheme: dark }` if the `theme` prop changes. **Header cells paint only LEFT+BOTTOM lines** (the container paints the single top line, and each cell above paints the shared bottom edge) — a TOP line on every cell doubles the borders between the level-0 block row and what's below into 2px.
- **Pinned mode: the `min-height: 300px` landmine.** The revo-grid library stylesheet sets `revo-grid { min-height: 300px }` (a Safari stretch workaround). Under the pinned 288px overlay (11 levels + the column-number strip) the data viewport is often shorter than 300px — the grid then refuses to shrink, overflows the clipped `.grid-viewport` and the trailing rows become unreachable while the footer still shows below. `.renovation-grid { min-height: 0 }` in globals.css beats the host rule — don't remove it. (Fullscreen "fixes" it only because the toolbar/footer collapse and the viewport clears 300px.)
- **Perf: the presence echo loop.** The grid's selection effect depends on `onSelectionChange`, which the workspace recreates whenever `room` changes; `room` changes on every presence echo (the server broadcasts the sender's own update back). With a selection, each cycle sent a fresh content-equal object → `setSelection` re-rendered the whole workspace + grid → new send → … a self-sustaining loop at WebSocket-RTT speed (measured: 31 presence sends per 1.5 s idle, 61 → 20 fps horizontal scroll, button animations janking). The workspace's `handleSelectionChange` drops content-equal payloads (`lastSelectionContentRef`); without a selection `setSelection(null)` bails out, which is why the loop only existed while a cell was selected. Don't remove the guard, and keep any new selection-callback out of effect deps or guard it the same way.
- **Placeholder add-row selection.** Focusing a cell (or selecting the «+» row) of the trailing `isPlaceholder` record-creation row does **not** emit a selection: the grid's debounced selection effect detects that every covered row is a placeholder and reports `{ label: null, cellKeys: [] }` — so nothing appears in the footer «Выделено» and nothing is broadcast over presence (a creation row has no persistence keys and never blocks anyone).
- **Dictionary export allow-lists.** Each export validates that every requested column key is in the server's per-section `ALLOWED_KEYS` (raw `src/raw_materials/export.py`, renovation `src/renovation/export.py`). A column missing from the list fails the export with «Экспорт содержит скрытый или недоступный столбец.» The **users** tables export with their real on-screen columns: raw users include `lastAuthenticatedAt`, renovation users include `role`, `block`, `lastAuthenticatedAt` (the enum codes are written as their keys); the renovation **assets** section exports its computed `repairCount`/`totalCost` columns too. Keep those key lists in sync with the grid descriptors (e.g. `grid-config.ts`) or the export breaks again.
